# LeanPhy

LeanPhy 是一个面向理论物理推导的 Lean 4 条件形式化验证库。研究者可以
把模型、物理约定、推导步骤和适用条件写成 Lean 命题，再由 Lean 内核检查
结论是否由这些前提推出。尚未完成的分析、建模选择、外部数值数据和失败的
探索分支会保留为假设或开放义务。

LeanPhy 建立在 Lean 和 mathlib 之上，不改变 Lean 的逻辑，也不自动判断某个
模型是否真实描述材料、实验或自然界。

## 当前版本快照

版本 `1.1.0`，本次整理日期为 **2026-10-08**。项目面向凝聚态、量子／统计
物理以及高能／场论中的探索性工作，目标是逐步接通：

```text
模型与约定 -> 形式操作 -> 物理读数 -> 适用域与误差证据
```

当前结果以有限维、有限模式、有限截断或明确给定的条件为主。有限定理不会
自动升级为连续极限、热力学极限或实验有效性结论。

## 范围和可信边界

“已检查”表示 Lean 证明项在列出的前提下通过内核。LeanPhy 不会自动证明：

- Hamiltonian、作用量或态确实描述某个真实系统；
- 连续、热力学、重整化或路径积分极限存在并收敛；
- 一般无界算符的定义域、自伴性和演化性质；
- 外部数值近似在没有 Lean 侧可靠性证书时的正确性；
- 给定有限真空是相互作用模型的基态。

这些边界属于项目接口的一部分。未完成的分析和物理解释会记录在研究包与
`VERIFIED.md` 中，不会因为代码编译成功而被隐藏。

## 项目结构

可复用证明放在 `LeanPhy/`，领域入口放在 `LeanPhy/Entry/`，研究包放在
`LeanPhy/Examples/`，可执行客户端放在 `Clients/`。为兼容 Lake 和下游项目，
根目录仍保留 `Main.lean`、`Prototype.lean`、`Check.lean`、`ClientMain.lean`、
`StrictClientMain.lean`、`Scaffold.lean` 六个基础入口。输入与外部报告放在
`examples/`。新增模块或文档前请先阅读[项目文件布局](docs/project-layout.md)。

## 后续完善方向

本轮功能调试和文档整理完成后，先暂停继续增加新的物理专题。下一阶段应优先
补足真实探索性研究中的公共功能，而不是重复增加固定案例：

1. 构造一般 Gaussian／热态，覆盖配对、源插入和时间有序多点关联。
2. 将有限响应扩展到一般实验室系驱动、平稳性、连续频率／输运读数，并控制
   有限振幅余项。
3. 把谱证书接到稳定低能子空间、Bogoliubov 约化、能带几何／拓扑和有限 RG
   耦合流。
4. 为有效理论补 Green 函数和边值误差、高阶场替换、IBP／EOM 算符基，以及
   选定的圈或非二次匹配任务。
5. 完善可靠数值包络、不确定输入传播、稀疏多体表达和性能证据。
6. 只有在具体模型给出必要分析前提时，再建设连续、热力学和非平衡极限桥。

当前优先级、依赖关系和验收标准统一维护在[建设路线](docs/roadmap.md)。
